# Navigate 项目架构

本文是当前架构的唯一正式说明。可视化见 [架构与产品图](./架构与产品图.html)（架构思路 / 产品视角可切换）。静态 `home.json` 快照、Cloudflare Sites/Wrangler 前端、美妆 HTML 日报基线和渠道实验输出都已退出运行时。

## 产品定位

Navigate 是面向中文读者的行业资讯工作台。用户用关键词或自然语言订阅主题，平台把目录网站和发现页收成统一内容池，再生成可在站内阅读的中文卡片和主题简报。

前台不展示评分、算法说明、额度消耗或采集过程文案。

## 运行时

Docker Compose 是正式部署：

```text
浏览器 / Cloudflare Tunnel
        │
        ▼
   web (nginx + Vue SPA)
        │  /api /health /docs
        ▼
   backend (FastAPI :8000)
        │
        ▼
   SQLite  backend/data/navigate.db
        ▲
        │
   crawler (同一镜像，run_due_sources --watch)
```

| 服务 | 职责 |
|---|---|
| `backend` | FastAPI、迁移、读写 SQLite |
| `crawler` | 每分钟检查北京时间 09:30 / 18:00 槽位，采集到期目录源，并回填中文卡片 |
| `web` | 构建后的 Vue 静态资源；把 `/api`、`/health`、`/docs` 反代到 backend |
| `cloudflared` | `network_mode: service:web`，公网域名打到同一 nginx |

数据库只挂载 `./backend/data`。改 Python 或前端源码需要重建对应镜像；只改库内数据不用重建。

本地联调也可以直接跑：

- API：`make backend` → `http://127.0.0.1:8000`
- 前端：`make frontend` → `http://127.0.0.1:3000`，开发态默认请求 `http://127.0.0.1:8000`

## 产品面

Vue 工作台是唯一读者界面，数据全部走 API，不再读静态快照。

| 界面 | 数据 |
|---|---|
| 为你精选 | 当前用户 active 主题的 `TopicMatch.include` 可读稿 |
| 我的主题 | 主题列表、预览、发现来源、暂停/删除 |
| 探索 | 网站目录源中有发布日期且正文可读的最新内容 |
| 每日简报 | 按主题 + 覆盖日排版；正文复用通用卡片，GET 不再另打 LLM |
| 管理 / 网站 | 补充网站、看通路、手动抓取、停用或移出爬不了的源 |
| 管理 / 账号 | 管理员维护用户 |

卡片字段来自 `content_editorial_zh`：中文标题、1–3 句摘要、标签。没有合格编辑件时才回退抽取式摘要。原文链接是次入口，标题不直接把读者送出站。

今日事件只展示跨来源、至少 2 个可读成员的聚类；单篇事件留在资讯流。

## 采集

必须区分两条路径，不要把 Firecrawl 和目录引擎当成同一件事。

### 1. 目录定时采集

`backend/config/sites.json` 投影到 `sources`。启用中的网站源由 crawler 在北京时间 **09:30** 和 **18:00** 各跑一轮。

五种执行引擎：

| 引擎 | 发现方式 |
|---|---|
| `static_http` | HTML 列表 + 详情 |
| `feed_direct` | RSS / Atom |
| `sitemap_http` | Sitemap + 详情 |
| `json_api` | 公开 JSON |
| `provider_api` | 授权第三方；当前仅 RedFox，来源默认停用 |

共享编排负责 HTTP、robots、重试、`PageSnapshot` 和统一入库。渠道适配器只校验渠道与引擎是否兼容。

管理员可在「网站」里临时抓取所选源；这是同一套引擎，不是 Firecrawl。连续失败会熔断 6 小时。有内容外键的源不能物理删除，只能停用并移出列表。

### 2. 主题发现

用户创建主题只编译意图，不联网。只有主动「发现来源」才消耗 Firecrawl 额度。

顺序：

1. 本地内容池先匹配。
2. DeepSeek 把意图编译成 `topic-search-plan.v1`。
3. Firecrawl **Search** 补 URL。
4. 先问五种引擎能不能抽出正文。
5. 引擎不够再走 Firecrawl **Scrape**。
6. 成功页写入共享内容池，并立即匹配该主题；发现源默认停用，不自动进每天两次的目录调度。

Firecrawl Map/Crawl/Agent 不对普通用户开放。

## 入库与加工

```text
Source
  → CrawlRun / PageSnapshot
  → RawItem（内容变化才追加不可变版本）
  → ContentItem / article.v1.1
  → 严格去重
  → TopicMatch（中英关键词 + 必要时 LLM review）
  → content_editorial_zh（DeepSeek 中文卡片，validator v6）
  → 探索 / 主题流 / 主题简报
  → Event（实体签名聚类，前台只展示多源事件）
```

中游还保留领域归属、实体主库、价值评分和领域 HTML 日报 CLI。它们服务治理与历史契约，**不是**当前读者主路径。读者主路径是主题匹配 + 通用中文卡片。

卡片生成约束：

- 证据先规则清洗网页壳、导航、广告、署名和阅读时长，再送给模型。
- 证据窗口：标题 + 摘要前 1200 字 + 洗净正文前 2500 字。
- 每次 2 篇，不设 `max_tokens`；北京时间日限 100 篇成功卡片。
- 按 `content_hash` + 当前 schema/validator 缓存；管道升级后旧卡片视为过期。
- 缺 key 或失败必须跳过，不能阻断采集。

主题简报：

- 选稿：该主题 `include` + 覆盖日时间窗。
- 文案：直接用 `content_editorial_zh`。
- 报头导语覆盖最多 3 条头条第一句；栏目按人事/融资/监管/产品/要闻，不用公司名当栏。

## API 面

读者与管理走 `/api/v1`：

- 账号：`/auth/*`、管理员 `/admin/users`
- 主题：`/topics`、`/topics/{id}/feed`、`/discover`
- 阅读：`/explore`、`/feed/for-you`、`/contents/{id}`
- 简报：`/topics/{id}/daily-reports/{date}`
- 事件：`/topics/{id}/events`、`/feed/events`
- 采集管理：`/sources`、`/sources/crawl-selected`、`/scheduler/*`

领域日报 `GET /api/v1/daily-reports/{date}?domain_key=beauty` 仍保留给历史 HTML 路径，前端工作台不使用。

## 配置与密钥

| 文件 / 变量 | 用途 |
|---|---|
| `backend/config/sites.json` | 网站、RSS、API 目录 |
| `backend/config/wechat_accounts.json` | RedFox 公众号清单，ready 但默认停用 |
| `DEEPSEEK_API_KEY` | 意图编译、主题复核、中文卡片 |
| `FIRECRAWL_API_KEY` | 主题 Search / 正文兜底 Scrape |
| `REDFOX_API_KEY` | 公众号 Provider，当前不作为稳定渠道 |
| `CLOUDFLARE_TUNNEL_TOKEN` | 隧道；只给 cloudflared 服务 |

根目录 `.env` 权限保持 600。`make check-secrets` 只报告 configured/missing。

## 明确不在现行路径

- `frontend/public/data/home.json` 与 `navigate-home.v1` 静态快照
- Cloudflare Vite plugin / Wrangler / OpenAI Sites Worker
- 公众号浏览器采集、离线导入、WeWe RSS
- 把 Firecrawl 当目录站的每日全站爬虫
- 打开简报时再为每个主题打一遍 `topic_content_editorial`
