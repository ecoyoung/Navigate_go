02 采集必须分成两条路

目录引擎稳、便宜、每天都要跑。Firecrawl 快，但按页计费，只能补缺口。不要把它们画成同一个爬虫。

目录定时 主路径

启用中的网站源，每天两次，走自己的引擎。管理员手动抓取也走这条，不走 Firecrawl。

HTML列表 + 详情
RSS / Atom条件请求
Sitemap地图 + 详情
JSON API公开接口
ProviderRedFox，默认停用

主题发现 主动才联网

创建主题只编译意图。只有用户点「发现来源」才消耗额度。

  1. 先匹配本地内容池
  2. DeepSeek 编成可审计的搜索计划
  3. Firecrawl Search 补 URL
  4. 五种引擎先抽正文
  5. 抽不出，再 Scrape

发现源默认停用，不自动加入每天两次的目录调度。

现行、计次免费的目录路径按次计费的发现路径

03 入库之后只加工一次

卡片是共享工件。探索、主题流、简报都读它，不要每个主题再写一遍。

01快照

外部响应进 PageSnapshot，可审计、可重放。

02原文版本

语义变了才追加 RawItem，旧版不改写。

03内容条目

投影为 article.v1.1，去重后进共享池。

04主题匹配

中英关键词先判；跨语种未命中再 LLM review。

05中文卡片

洗净后再送 DeepSeek。日限 100，不设 max_tokens。

06产品面

探索 / 为你 / 主题流 / 主题简报。GET 简报不再打模型。

已退出

不要再画进来

home.json 快照、Cloudflare Sites 前端、公众号浏览器采集、打开简报时再写一篇 topic_content_editorial。

01 谁在用，各自完成什么

订阅读者

持续盯一个行业问题

对象是意图，不是某个网站。例如「具身智能创业融资」，而不是「订阅 36氪」。

  • 创建主题立刻看到池内匹配，不联网
  • 在站内读完凝练卡片，原文只是次入口
  • 每天看一份按事件栏目排好的简报
管理员

把来源养在目录里

补充网站、看通路能否打通、手动抓一轮、把爬不了的源移出列表。

  • 失败源仍可选中并移除
  • 有内容外键的源只能停用，稿件保留
  • 发现来源不会自动变成每日两次的目录站

02 五个界面怎么分工

为你

合并已订阅主题

只放 TopicMatch.include 的可读稿。这是默认工作台，不是门户首页。

我的主题

管理意图

创建、暂停、删除、预览。发现来源是显式动作，创建主题不是。

探索

看目录刚取回的稿

网站源里有日期、正文可读的最新内容。手动抓完应出现在这里。

每日简报

成品报纸

按主题和覆盖日排版。导语最多三条头条第一句。栏目是人事 / 融资 / 监管 / 产品 / 要闻。

今日事件

只放多源聚类

至少两篇可读成员才进事件栏。单篇留在资讯流，避免把每篇稿再列一遍。

管理

网站与账号

通路标签、临时抓取、删除失败源。前台不写额度或爬虫过程。

03 价值单元是卡片，不是标题列表

content_editorial_zh

站内读完的最小成品

中文标题、一到三句事实摘要、可选标签。英文稿要先译成中文卡片。清洗网页壳是规则，写卡片是模型；两者不能互相替代。

没有合格编辑件时才回退抽取式，不能把导航、广告、署名送进读者视野。

来源名 · 发布日期

中文标题

一到三句已洗净的事实摘要。点击留在本页。原文是次入口。

04 读者的一天

1

写下意图

编译主题。此时只查共享池，不花 Firecrawl。

2

读卡片

为你精选和探索都是同一类卡片。目录每天两次在背后更新。

3

不够再发现

主动点发现，Search 补 URL，引擎优先，Scrape 兜底。

4

收口成简报

用已有卡片排版，不再摘要一次。栏目按事件，不按公司名。

05 产品明确不做

不展示过程额度、算法、评分、抓取日志不进读者文案。
不自动全网爬Firecrawl 不是目录站的每日爬虫，也不对普通用户开放 Crawl。
不把标题当外链列表主点击留在站内卡片，而不是跳原文。
不为每个主题重写简报复用通用卡片。打开简报是读，不是生成。
